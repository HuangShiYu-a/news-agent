# 演示录屏脚本（≤ 3 分钟）

录制工具：`Win + G`（Xbox Game Bar）或 OBS。使用演示模式（`NEWS_SOURCE=demo`，默认）保证过程可复现。建议先完整走一遍流程热身再开录；模型每次的工具选择略有差异属正常现象——这本身就是"调用顺序由 LLM 决定"的证明，讲出来是加分项。

前置：服务已启动（`.venv\Scripts\python -m uvicorn app.main:app --port 8000`），浏览器打开 http://127.0.0.1:8000 ，偏好保持默认（AI Agent / 开源模型 + function calling / MCP / 多模态）。

| 时间 | 操作 | 口播要点 |
|---|---|---|
| 0:00–0:20 | 展示页面：徽标"演示模式 · 虚构测试新闻样例"、右上角"模型 deepseek-chat · 每日定时 08:00" | 前端零依赖单页；右上角即定时任务配置展示；徽标如实标注样例数据 |
| 0:20–0:40 | 展示订阅设置表单（姓名 / 身份 / 话题 / 关键词），点"保存设置" | 偏好存 SQLite 单行设置表；生成时写入任务工作目录的 preferences.md |
| 0:40–1:30 | 点"立即生成"，停在生成卡片看轮询：工具调用逐条出现（典型顺序：read_file preferences.md → list_dir news → read_file ×3 → write_file briefing.md） | **核心卖点**：调用哪个工具、调几次、何时停，全部由 LLM 决定；每次调用有参数摘要、结果摘要、状态、耗时；程序只保证边界（路径、命令白名单、轮数、超时） |
| 1:30–1:50 | 任务完成后看简报：逐条含 `[news_id]`、链接、发布时间、一句话摘要，按偏好相关度排序 | 产物校验：news_id 必须属于本次材料、链接逐字一致、不得重复——引用可追溯（不是事实核查）；校验失败会带错误反馈在同一段对话里修正一次 |
| 1:50–2:20 | 把话题改为"AI 芯片、硬件"，关键词改为"推理加速、能效比"，保存 → 再次"立即生成" → 对比两次简报 | 同一批材料、不同偏好、结果前两条变为仅有的两条硬件新闻——筛选差异可解释 |
| 2:20–2:40 | 滚动历史简报列表（含一次失败任务也如实展示） | 简报随任务存 runs 表；失败原因落库可查 |
| 2:40–3:00 | （时间充裕时）切到终端跑 `.venv\Scripts\python -m pytest tests -q`：101 项通过 | 循环正确性与安全边界（路径越界、bash 元字符、白名单外命令）、产物校验（含交换链接拒绝）有测试兜底 |

收尾口播（约 10 秒）：外围流程固定、Agent 决策自主；站内通知是题目允许的自选推送位置；全部设计决策见 docs/design.md。

## 如果被追问，准备好的回答

- **为什么不让模型联网搜索？** 演示可复现 + 引用可追溯（news_id 锚定）；真实模式已接 RSS，联网搜索列为演进方向。
- **为什么推送是站内的？** 题目明说"推到哪里由你自己决定"；demo 定位不引入外部服务与凭据；生成与发送的边界已存在，挂渠道适配器即可扩展。
- **bash 为什么只有三条命令？** 题目要求工具真实可用，不要求通用 shell；不经 shell 解释器（shell=False 直 exec）后注入面从根上消除，管道/重定向/组合天然不可能。
