## 设计评审的三轮收敛

初版设计（v1.1 / v1.2）偏"稳妥完整"，评审中被逐轮收缩为 demo 定位：

1. **v1.3（14 项实施决策 D1–D14）**：钉死执行模型（纯同步核心 + 接口层 to_thread）、产物契约（briefing.md 方括号 news_id）、校验失败同对话修正一次、trigger 语义、工具路径约定、材料布局、tzdata / 幂等建表 / 调用超时等。
2. **v1.4**：推送从 SMTP 邮件改为钉钉群机器人 webhook——但"换渠道没有真正减少复杂度"（授权码换成了 webhook 一串配套工作），随即被第三轮推翻。
3. **v1.5（最终形态，D15 废止，新增 D16–D22）**：外部推送全删，改站内未读通知；bash 从六命令通用解析器收缩为 `pwd / ls / head` 白名单 + `shell=False` 直 exec（不引入 shell 解释器，注入面从根上消除，也不再依赖 bash.exe）；删除第六个工具 query_news（与 read_file / search_content 重叠，五个工具与题目清单一一对应）；单用户三表（settings / runs / tool_calls）；删除统计式验收门槛（通过率 / 用例数 / 行数），改为实测检查单。

收缩原则（评审中确立）：**外围流程可以固定（调度、抓取、校验、通知），Agent 内部决策不能固定；真实 Agent 循环、简单页面、可运行交付优先，其余基本可靠即可。**

## 三阶段验收实测记录

### 阶段一：核心能跑（2026-10-17）

- mock 单测全绿：消息序列（assistant 回填、多调用逐个回传、最终回答回填对话）、工具错误结构化回传不终止循环、轮数超限、轮间软时限、输出截断 / 空回复 / 基础设施错误、修正续跑共享预算；
- 安全边界测试：路径越界（`..`、绝对路径；符号链接用例按环境条件跳过——Windows 需开发者模式）、bash 元字符 / 白名单外命令 / 非法选项 / 路径越界全部拒绝；
- **真实 DeepSeek 端到端一次成功**：6 次工具调用、8.1 秒、首轮校验通过（news_id 与链接逐字一致、按偏好相关度排序）；
- 期间修复真实缺陷 1 个：模型最终回答未回填 assistant 消息，导致修正续跑时模型看不到自己此前的完成表态。

### 阶段二：页面能演示（2026-10-17）

- 浏览器真实操作全链路：保存偏好 → 立即生成 → 轮询见工具轨迹逐条出现 → 简报渲染；
- 偏好差异：切换为"AI 芯片 / 硬件"后，简报前两条精确变为材料中仅有的两条硬件新闻（N0005、N0014），Agent / MCP 条目让位——差异可解释；
- 并发防护：执行中再次点生成返回 409；
- 轮询流畅性：LLM 调用执行期间 API 轮询延迟 5–30ms（to_thread 生效，事件循环未被阻塞）；
- RSS 部分失败：配置一个 DNS 失效源 + 真实 Hacker News 源，任务继续成功，fetch_report 记录失效源明细与成功源 12 条；
- 进程强杀后重启，遗留执行中任务自动标记 `failed / interrupted`。

### 阶段三：满足交付（2026-10-18）

- 定时触发：测试服务器设 `DAILY_RUN_AT=15:36`，**15:36:00.035 精准触发**，真实生成成功、is_read=0（未读）；
- 未读通知闭环：接口返回未读 → 再次触发定时入口被防重跳过（当日 scheduled 任务数保持 1）→ 查看后未读清零；
- 全新 clone 计时：克隆（确认无 .env / data / venv 泄漏）→ venv → 依赖安装（清华镜像 49s；直连 PyPI 实测 337s，镜像建议已写入 README）→ 88 项测试通过 → 真实 LLM 端到端成功 → 服务器启动正常；克隆内功能验证合计 14s。

## 模型自主性的实测例证

三次成功生成中，模型对同一任务采用了三种不同的工具序列：

1. `read_file(preferences.md) → list_dir(news) → read_file ×3 → write_file`
2. `read_file(preferences.md) → list_dir(news) → read_file(hnrss) → search_content ×4 → write_file`（真实 RSS 模式，材料较大时自主改用搜索）
3. `list_dir(".") → read_file(preferences.md) → list_dir(news) → read_file ×3 → write_file`

工具调用的顺序、次数、何时停止均由模型决定，程序不预设、不强制——这是题目核心要求 ① 的直接证据。全部调用逐条落库（tool_calls 表），页面可回放。

## 环境实测备忘

- RSS 源可达性（2026-10-17 无代理直连实测）：DeepSeek API / hnrss / TechCrunch / 机器之心 / 量子位 / Solidot 全部可达；量子位与 Solidot 需浏览器 User-Agent（默认 curl UA 返回 403），抓取器已显式设置；
- Windows 细节：Python 3.10.11（`py` 启动器）；APScheduler 必须显式 Asia/Shanghai 且依赖 pip 的 tzdata 包；文件读写显式 UTF-8；bash 工具直接执行 Git for Windows `usr/bin` 下的命令二进制，零额外依赖。
